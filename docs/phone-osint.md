# Phone OSINT / Phone Clue guardrails

Phone OSINT workflows must be used only for lawful, authorized, and ethical research with data minimization.

## Operator limits

- Use only with explicit authorization, personal self-assessment, or clearly permitted defensive work.
- Treat external search results as leads, not proof.
- Validate source context, publication date, author identity, repeatability, and false-match risk before conclusions.
- On mobile clients, open routes sequentially to reduce popup blocking and accidental over-launch.
- Prefer exact-scoped queries and avoid broad expansion that increases unrelated personal data collection.

## Sensitive route controls

The phone catalog marks sensitive and high-signal routes. Sensitive routes require an explicit authorized-use confirmation before launch.

High-risk route classes include:

- breach and exposure awareness
- security reputation checks
- messaging and profile linkage clues

## Privacy and telemetry

Telemetry should capture only action metadata (which tools were opened or copied) and non-identifying phone fingerprints (digit count, last 4 digits, international-prefix flag).

Do not store full phone numbers in telemetry or notes logs.
